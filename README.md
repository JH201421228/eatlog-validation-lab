# EatLog Validation Lab

EatLog의 중간평가 우려를 재현 가능한 실험으로 확인하기 위한 개인 연구 저장소입니다.

## 평가 구분

1. `experiments/contracts/`: 최초 BE/AI 합성 계약 실험. 계산과 출력 검증에 관한 결과이며 실제 사진 정확도 표본이 아닙니다.
2. `data/`: 공개 실측 정답 데이터의 출처, 라이선스, 표본 manifest, 정답 및 데이터 품질 기록. 원본 사진은 저장소에 올리지 않습니다.
3. `scripts/data/`, `scripts/evaluate/`, `evaluation/`: 공개 데이터 수집과 실제 모델 평가, 동일 응답에 대한 이전/개선 후처리 비교.

실제 모델 평가 예산은 사용자가 승인한 **전체 US$30 이하**입니다. 요청별 사용량과 보수적인 비용 상한을 기록하며, 파일 수나 성공 응답 수를 독립적인 평가 표본 수로 대신하지 않습니다.

## 문제와 검증한 가설

| 우려 | 가설과 코드 변경 | 검증 결과·범위 |
| --- | --- | --- |
| 비유한 숫자·잘못된 타입·후보 중복·불충분한 검색 근거가 API 결과에 포함됨 | AI 응답의 숫자와 구조를 검사하고, 음식별 후보 정렬·중복 제거 후 제한하며, 제품 검색 근거와 추천 후보를 검증 | 합성 계약 사례 59개: 15 → 59 충족, 포함된 정상 대조 13/13 유지. 실제 사진 정확도와 별개 |
| 포장 전체 열량에 내부 낱개 수를 중복 적용하거나 반개 섭취를 정수로 환산함 | BE에서 같은 포장 중량 기준의 섭취 비율로 계산하고, 원래 개수와 화면 표시 개수를 분리하며 명시적 0 kcal를 보존 | 합성 산식 사례 18개: 9 → 18 충족, 기존 정상 9/9 유지 |
| BE 영양 계산의 표시 단위와 FE가 읽는 포장 원문의 용량이 다름 | BE 응답의 `size_text`를 표시 단위당 g/ml로 투영하고 원래 입력 객체를 보존 | 동일 산식 사례를 활용한 표시 사례 12개: 4 → 12 충족. 기존 FE 함수를 읽어 실행했으며 FE 수정 없음 |
| 성공 응답만으로 실제 음식량·칼로리 정확도를 주장하기 어려움 | 공개 정답 사진으로 실제 모델을 한 번 호출하고, 같은 원본 응답을 수정 전/후 AI·BE 코드에 재생 | 본평가 1,000건 선정, 999건 호출, 유효 영양 예측 994건. 수정 전후 예측 변경 0건: 이 자료에서 사진 영양 정확도 개선은 관측되지 않음 |

합성 사례 수를 실제 음식 사진 수와 합산하거나, 서로 겹치는 산식·표시 사례를 독립 표본으로 세지 않습니다. 실험 가설·실행 명령·개별 사례 결과는 [계약 실험](experiments/contracts/README.md)과 각 하위 문서에서 확인할 수 있습니다.

## 공개 사진 평가

- 출처: Google Research의 [Nutrition5k](https://github.com/google-research-datasets/Nutrition5k), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 재료별 저울 중량과 영양 DB 계산값을 사용합니다. 열량계 실측이 아닙니다.
- 모델: `gemini-2.5-flash`, 사진 1장, 사용자 설명·정답 주입 없음. 평가 모델을 확인한 것이며 현재 운영 서버의 모델 설정을 확인한 것은 아닙니다.
- 유효 사전 점검 20건, 고정 본평가 대상 1,000건. 본평가 중 공식 이미지·영상이 모두 없는 1건은 실패 분모에 남깁니다. 사진을 확보한 999건과 별도로 집계합니다.
- 본평가 전 정답 메타데이터를 점검하여 0 영양 placeholder 238건, 불일치/단위 이상 37건, 빈 접시 2건을 제외했습니다. 최초 사전 점검 호출 이후 발견된 문제이며, 정답 기반 모델 점수를 보고 선별한 것이 아닙니다. 선정 변경 이력과 제외 사유를 보존합니다.
- 누락된 A 카메라는 같은 음식의 공식 파일 존재 여부만으로 A→B→C→D 순서의 첫 카메라, 첫 프레임으로 결정했습니다. 원본이 전혀 없는 음식을 새 음식으로 교체하지 않았습니다.
- 기본 비교는 영양 DB 매칭·외부 검색·사용자 습관 보정을 제외한 경로입니다. 서비스 전체의 실제 성능이나 한국식·포장 OCR·사용자 리텐션 개선을 대신하지 않습니다.
- 공식 물리 접시 식별자가 없어 시간·재료 중량으로 추정 중복 그룹을 분리했습니다. 완전한 독립성 및 모델의 공개 자료 사전 학습 노출 여부는 확인할 수 없습니다.

사전 계획과 지표 정의는 [평가 프로토콜](evaluation/PROTOCOL.md)에 있습니다. 원본 응답은 개인 정보와 요청 헤더를 제외한 형태로 보존하고, 이미지/요청/코드/선정 해시로 연결합니다. 원본 사진·영상은 로컬에만 보관하며 재수집 가능한 출처와 무결성 기록을 Git에 저장합니다.

원본 누락 1개, API ReadTimeout 3개, 음식 후보가 없는 응답 2개를 전체 분모에 유지했습니다. 음식 후보가 없는 두 이미지를 사후 열람한 결과 스마트폰/촬영장치와 그릇 아래쪽이 보였습니다. 이를 모델의 잘못된 음식 거부로 단정하지 않습니다. [시각적 정합 한계](review/source_visual_limitations.json)는 사후 관찰이며, 이에 따라 표본이나 정답을 바꾸지 않았습니다. 전체 이미지의 음식 가시성과 라벨 의미를 사람이 전수 검수한 것은 아닙니다.

과거 브랜드 음식 사진 23장의 29.4% 오차와 이번 수치는 자료 분포·모델 조건이 달라 직접 전후 비교할 수 없습니다. 결과 해석과 단계별·촬영각도별·신뢰도별 분석은 [평가 결과](evaluation/RESULTS.md), 개별 결과는 `evaluation/results/`에 있습니다. 독립적인 지표·비용 재계산 [20개 검사](review/final_audit.json)를 통과했습니다.

유료 요청은 본평가 999개와 예비 23개(정답 품질 제외 3개 포함)로 총 1,022회입니다. usage 확인분 추정 비용은 **US$1.9125488**, timeout 3건의 보수적 미확인 예약액 US$1.50을 포함한 장부는 **US$3.4125488**입니다. 승인 한도 US$30 이내이며 청구서 확정액은 아닙니다. 자동 재시도는 하지 않았습니다.

### 후속 정확도 확인 — 완료, 정확도 후보 기각

개발 데이터에서 선별한 `flash35_minimal`을 사전 동결한 잔여 155개 그룹에서 기준 모델과 비교했습니다. 후보의 열량 MAE는 31.8% 낮았고 paired bootstrap 95% 구간도 개선 방향이었지만, 유효 열량 예측 수가 **153→151**로, 전체 155개 중 오차 ±15% 이내 수가 **30→29**로 감소했습니다. 사전 기준에서 두 coverage/accuracy gate를 실패해 최종 판정은 **기각**입니다. 정확도 AI 후보는 병합하거나 배포하지 않으며 추가 호출·재시도·재튜닝도 하지 않습니다.

확인 세트의 누적 비용은 과거 요청을 포함해 usage 추정 **US$7.3393675**, charged/reserved **US$12.3393675**입니다(승인 한도 US$30). 상세 지표와 판정은 [최종 판정](experiments/accuracy_followup/final_decision.json), [확인 요약](experiments/accuracy_followup/results/confirm/summary.json), 완료 상태와 비용 요약은 [completion manifest](experiments/accuracy_followup/completion_manifest.json), 실행·실패 분모·gold 접근 기록은 [후속 실험 기록](experiments/accuracy_followup/README.md)에 있습니다. frozen service prototype과 mock 기반 258개 테스트 통과 기록은 [service_candidate](experiments/accuracy_followup/service_candidate/)에 보관했습니다.

## 서비스 반영과 실험 보관 위치

기존 BE·AI robustness 개선의 AWS 배포를 확인했습니다. 별도로 BE의 모호하지 않은 AI-call retention linkage fallback도 commit `c81ec8c4abfad226adf06698c2b42e05b1dd8f4d`로 배포됐습니다(GitHub Actions run `40176912543`, health `ok`). 이 변경은 향후 명확한 candidate-parent 관계만 보존하며 과거 backfill이나 retention 개선 효과를 주장하지 않습니다. 정확도 후속 AI 후보는 기각되어 배포하지 않았고, 기존 AI robustness 버전 `a860b2fb3a2c53a4484ddc6673d86d938f039171`을 유지합니다. 실험 자료는 사용자 요청에 따라 이 개인 저장소로 이관했으며 팀 저장소에는 서비스 코드와 필수 회귀 테스트를 유지합니다. 이미 푸시한 Git 이력은 다시 쓰지 않았습니다. PR·기존 배포 근거는 [배포 및 이관 기록](experiments/contracts/deployment_and_relocation.json), BE retention-linkage의 배포·health 확인은 [deployment.json](experiments/accuracy_followup/retention_linkage/deployment.json)에 있습니다.

| --- | --- | --- |
| BE | `7249699d09fd0f0d34080990c77c63328da01567` | `c81ec8c4abfad226adf06698c2b42e05b1dd8f4d` |
