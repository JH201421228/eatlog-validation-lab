# Nutrition5k 실제 사진·정답 평가 자료

이 디렉터리는 합성 예제나 모델이 만든 정답이 아닌 **공개된 실제 음식 촬영 자료와 원본 중량·영양 라벨**을 담는다. 최종 목록은 `selection_manifest_v3.jsonl`, 다운로드 상태·실제 파일 해시는 `manifest.jsonl`이다. 원본 사진·영상·실행 도구 바이너리는 Git에 올리지 않는다.

## 출처와 사용 허가

- 공식 배포: [Google Research Nutrition5k](https://github.com/google-research-datasets/Nutrition5k), [공식 GCS 버킷](https://console.cloud.google.com/storage/browser/nutrition5k_dataset).
- 논문: Quin Thames 외, *Nutrition5k: Towards Automatic Nutritional Understanding of Generic Food*, CVPR 2021, pp. 8903–8911. [논문](https://arxiv.org/abs/2103.03375).
- 전체 데이터 라이선스: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 원 저작자·출처·라이선스 링크를 표시하고 변경을 밝히면 재배포·가공이 허용된다. 공식 README의 해당 고지와 출처 commit을 `source/README.upstream.md`, `source/provenance.json`에 보존했다.
- 이 저장소의 변경: 부분 표집, 원본 라벨의 형식 변환, 출처 품질 점검, 추정 중복 그룹 생성, 영상에서 첫 프레임 추출. 원본 영양 숫자를 보정하거나 모델 출력으로 대체하지 않았다.
- 촬영 대상은 구내식당 식사이며 프로젝트 사용자의 사진·대화·개인정보를 사용하지 않았다.

## 정답의 의미와 단위

논문의 수집 방법은 재료/조리 음식이 접시에 추가될 때 질량을 측정하고, 알려진 레시피와 USDA의 영양 밀도로 영양 총량을 계산한다. **질량은 측정값, 열량·영양소는 측정 질량과 데이터베이스에 기반한 라벨**이다. 열량계로 직접 측정한 열량이라는 뜻은 아니다. 원 논문의 저울 정밀도는 ±1g이며, 레시피 구성과 실제 음식의 차이 등 원자료의 오차 가능성은 남는다.

`truth`는 사진 전체 접시를 기준으로 한다.

| 필드 | 단위 | 원본 CSV의 0부터 센 열 번호 |
| --- | --- | --- |
| `calories_kcal` | kcal | 1 |
| `mass_g` | g | 2 |
| `fat_g` | g | 3 |
| `carbs_g` | g | 4 |
| `protein_g` | g | 5 |

실제 배포 CSV는 `dish_id` 포함 **기본 6열 + 재료별 7열 반복**이다. 재료 7열은 ID, 이름, 질량 g, 열량 kcal, 지방 g, 탄수화물 g, 단백질 g 순서다. 공식 README의 `num_ingrs`/반복 열 수 설명과 실제 파일 형식은 다르므로 실제 5,006행의 구조를 검증했다. 별도 `ingredients_metadata.csv`의 밀도로 평가 정답을 새로 생성하지 않았다. `label_mapping_validation.json`은 독립적인 CSV 열 재확인 결과다.

## 모집단과 사전 품질 점검

원본 메타데이터는 5,006개 dish ID, 공식 overhead RGB 객체는 3,490개다. 공식 RGB 분할은 train 4,059개, test 709개이며 Cafe 2의 238개는 이 분할에 포함되지 않는다.

원본 데이터만으로 아래 조건을 고정하여 검사했다. **모델 성능·오답 크기·사진이 쉬워 보이는지에 따라 정답을 골라내지 않았다.** 숫자 임계값은 본 실험의 보수적인 정합성 허용 범위이며 데이터셋이 보장한 오차 분포는 아니다.

| 조건 | 처리 및 근거 |
| --- | --- |
| NaN, Infinity, 음수, 0 이하 접시 질량, 잘못된 열 구조 | 유효한 수치 라벨이 아니므로 제외. 실제 해당 행 0개. |
| 접시 영양 총량은 모두 0인데 재료 열량 합계가 1 kcal 초과 | 0을 실제 무열량 정답으로 오인하지 않도록 제외. Cafe 2 전체 238개가 해당. |
| 접시 질량과 재료 질량 합계 차이 > max(5g, 접시 질량의 2%) | ±1g 측정·반올림에 여유를 두되 명백한 총량 불일치를 제외. |
| 접시 열량과 재료 열량 합계 차이 > max(1kcal, 접시 열량의 1%) | 부동소수점·레시피 반올림보다 큰 합계 불일치를 제외. |
| 열량 > 9 × 질량(g) + 5 kcal | 표시된 주요 영양소의 에너지 밀도 상한에 반올림 여유를 둔 점검. |
| 지방+탄수화물+단백질 질량 > 접시 질량 + max(2g, 2%) | 총 음식 질량보다 주요 영양소의 합이 커지는 단위 오류 점검. |
| 원본 재료가 `plate only` (`ingr_0000000423`)뿐 | 실제 음식 영양 평가에서 빈 접시 대조군 2개 제외. |

**중복 사유를 한 행으로 합친 제외는 277개**다: Cafe 2의 238개 + Cafe 1 총량/단위 불일치 37개 + 빈 접시 2개. 적격 원본은 4,729개다. 한 행이 여러 조건에 걸릴 수 있으므로 사유별 빈도 합계와 제외 행 수는 다르다. `label_quality_exclusions.jsonl`에 모든 ID, 원래 접시 값, 재료 합계, 위반 사유를 기록했고 `label_quality_audit.json`에 중복 허용 빈도와 서로 배타적인 사유 조합 집계를 모두 제공한다.

초기 v1 표집 후 이 문제가 발견되었다. 이때 예비 점검용 모델 호출은 이미 진행되고 있었지만, 영양 점수를 계산하거나 데이터 담당이 모델 응답을 읽지는 않았다. **v2 품질 규칙과 목록 고정은 본 평가 호출·영양 점수 확인 전**이며, v1 및 제외된 예비 응답의 이력은 지우지 않았다. v2 고정 시각은 2026-10-25 06:39:36 UTC다.

## 중복 가능성, 표집, 평가 분리

같은 접시에 재료를 추가한 증분 촬영은 서로 다른 dish ID를 가질 수 있다. 공식 물리 접시 그룹 ID가 없으므로 다음 조건의 전이적 연결로 **추정 그룹**을 만들었다.

1. 같은 구내식당에서 600초 이내 촬영.
2. 작은 재료 집합이 큰 집합에 포함되고 기존 재료의 질량이 감소하지 않음(2mg 수치 허용).
3. 적어도 하나의 1g 이상 재료가 같은 질량(±2mg)을 유지함.

모든 연결과 멤버를 `group_edges.jsonl`, `groups.jsonl`에 남겼다. 이 방법은 잠재 중복을 보수적으로 묶지만 별개 접시를 과하게 합치거나 실제 반복을 놓칠 수 있다. 84개 추정 그룹이 공식 train/test를 걸쳐 있어 **공식 접시 정체성의 증명으로 해석할 수 없다**. 최종 1,020개는 서로 다른 dish ID 및 서로 다른 추정 그룹이며, 엄밀한 통계적 독립성을 보장하지 않는다.

표집 seed는 `eatlog-public-nutrition5k-2026-10-25-v1`이다. 문자열의 SHA256 순서로 그룹과 대표 dish를 결정하며, 사용 가능한 overhead RGB를 우선한다. 그룹당 한 장만 선택한다. v2 품질 검사 후 사용 가능한 overhead 그룹 856개를 모두 사용하고 필요한 164개 그룹은 측면 영상의 고정 첫 프레임으로 보충했다. 원본 전체 181.4GB 아카이브는 다운로드하지 않았다.

| 용도 | 수량 | 공식 train | 공식 test | 영상 유형 |
| --- | ---: | ---: | ---: | --- |
| 예비 동작 점검 | 20 | 17 | 3 | overhead 20 |
| 고정 평가 세트 | 1,000 | 852 | 148 | overhead 836 + 측면 첫 프레임 164 |

v1 예비 20개 중 유효한 Cafe 1의 17개를 유지하고 새 3개를 예비에 추가했다. v1 예비에 포함된 모든 그룹은 최종 평가에 편입하지 않았다. 예비의 목적은 네트워크·JSON 완결성·토큰 설정 확인이며 정답을 보고 프롬프트/룰을 맞추는 용도가 아니다.

코드 호환을 위해 분할 값은 `pilot`/`blind_test`이나, 보고서에서는 **고정 평가 세트**라고 부른다. 공개 벤치마크이므로 모델 사전학습 노출 여부는 알 수 없다. 공식 train 출신 데이터가 포함된 점을 공개하며 공식 test 출신과 이미지 유형별 결과를 나누어 보고한다. 한국 음식, 스마트폰 촬영 조건, 포장 표기·음료 OCR의 대표성을 주장하지 않는다.

## 원본 파일 누락에 대한 v3 기록

선정된 일부 측면 영상에는 공식 버킷에 `camera_A.h264`가 없었다. 동일 dish·그룹·정답·분할을 유지하고, **A → B → C → D 중 실제 존재하는 첫 카메라의 프레임 0**을 쓰도록 출처 해석만 수정했다. 이미 A가 존재한 샘플의 사진은 바꾸지 않았다. 카메라별 구도 차이는 결과의 제한이며 원본 객체 URL·generation·MD5와 변경 행을 `source_resolution_amendment.json`에 보존한다.

이 수정 시점에는 검증된 overhead 이미지 일부의 본 평가 호출이 시작된 상태였다. 데이터 담당은 모델 응답·영양 점수를 보지 않았고, 누락된 파일의 공식 존재 정보만 사용했다. 음식이나 유리한 프레임을 새로 고르지 않았다. 이 시점을 숨겨서 전체 절차가 모든 호출 전에 사전 등록되었다고 쓰면 안 된다.

실제로 A가 없던 7개 중 6개는 B를 사용했다. 나머지 `dish_1564415499`는 overhead와 모든 측면 원본이 없으므로 분모에 남긴 출처 누락이다. **최종: 평가 1,000개 선정 / 실제 평가 사진 999개 / 공식 원본 누락 1개**, 예비 사진은 별도 20개다. 사용 가능한 1,019개 전체는 overhead 856개(640×480), camera A 157개와 B 6개(1920×1080)다. 총 실제 이미지 578,224,710 bytes, 원본 이미지·영상 3,276,770,779 bytes를 검증했다.

최종 QA에서 1,019개 원본의 공식 MD5·실제 이미지 SHA256, 163개 원본 영상 해시를 전수 재확인했다. 파일 SHA256 중복 0, 디코딩한 픽셀 중복 0, 디코딩 실패 0, 상수·거의 검정 이미지 0, 예비/평가 dish 및 추정 그룹 교집합 0이다. 1,020개 접시 라벨과 6,364개 재료 라벨의 원본 CSV 열 매핑도 독립적으로 재확인했다. 원본 누락 1개가 있으므로 무결성 검사 통과를 '선정된 파일 모두 존재'로 해석하면 안 된다.

최종 규칙 이후 실패는 같은 출처를 재시도하고 고정 분모를 유지한다. 모델 성과를 보고 다른 음식으로 교체하지 않는다. 다운로드 파일은 해시와 PNG 구조를 검증한 임시 파일에서 최종 경로로 원자적으로 공개한다. 모델 입력 담당도 `download_status=ok`와 실제 SHA256 일치를 확인한 파일만 읽는다.

`image_path`는 **저장소 루트 기준 상대 경로**다. 평가 모델에는 이미지와 고정 프롬프트만 전달해야 하며, `truth`, 재료 목록, 정답 메타데이터는 프롬프트에 포함하지 않는다.

## 재실행

원본 metadata와 최종 선정 manifest는 저장소에 포함되어 있으므로 일반적인 재실행에는 다음으로 충분하다. 수집기는 표준 라이브러리만 사용하고, 픽셀 디코딩 감사에는 Pillow가 필요하다. Windows 도구 준비는 고정된 wheel/실행 파일 SHA256을 검증하고 로컬 캐시에만 추출한다.

```powershell
python scripts/data/prepare_ffmpeg.py
python scripts/data/collect_nutrition5k.py download --workers 8 --ffmpeg data/downloads/tools/ffmpeg.exe
python scripts/data/collect_nutrition5k.py validate
python scripts/data/collect_nutrition5k.py audit-labels
python scripts/data/verify_dataset.py
python scripts/data/validate_images.py
```

완전히 새 표본을 만들려는 재현 연구에서는 별도 디렉터리에서 `fetch-sources`, `prepare`를 실행한다. 기존 고정 파일을 덮어쓰지 않도록 수집기가 차단한다. 새로 생성한 v2 표본의 바이트 해시가 원본 v2와 정확히 같음을 `reproducibility_check.json`으로 확인했다. v3는 같은 표본의 공식 카메라 존재 메타데이터를 해석한 변경이며 해당 객체 generation이 고정되어 있다.

이 데이터 수집 단계의 유료 모델 호출은 **0회**다. 모델 평가·비용·지표는 별도 `evaluation/` 담당 산출물로 확인해야 한다.

도구 라이선스도 데이터 라이선스와 구분한다. `imageio-ffmpeg` 패키지는 BSD 2-Clause이며 포함된 ffmpeg 실행 파일은 GPL 설정의 별도 빌드다. 도구 버전·실행 파일 SHA256·라이선스 출력은 `source/ffmpeg_provenance.json`, `source/ffmpeg_license.txt`에 보관한다. wheel과 실행 파일은 Git에 재배포하지 않는다.
